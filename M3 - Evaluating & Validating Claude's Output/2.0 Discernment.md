### 1. Summary

* **Problem Statement:** Evaluating LLM output based on subjective feelings or linguistic fluency is an anti-pattern. Fluent, well-structured text can easily conceal fatal omissions, hallucinated parameters, or unverified claims, introducing compliance and operational risk.
* **Core Concepts:** As detailed in [Evaluating & Validating Claude's Output](https://anthropic-partners.skilljar.com/path/claude-certified-associate-foundations/evaluating-validating-claudes-output/486637/scorm/38okzl3o5djsl), output verification must rely on a standardized protocol that checks responses against three fixed references:
    * **Requirements** (did it answer every prompt request?),
    * **Source Material** (does it match provided documents?), and
    * **Professional Standards** (does it satisfy domain-specific rigor?).
* **Key Technical Takeaways:**
    * **Stakes Calibration:** Review depth must be dynamically calibrated based on domain risk (e.g., zero-tolerance compliance vs. low-stakes internal brainstorming).
    * **Three-Way Triage Protocol:** Model outputs must be systematically categorized as *Ready to use*, *Needs revision*, or *Needs human override*.
    * **Accuracy vs. Completeness:** Accuracy verifies the correctness of present information, while completeness explicitly audits for missing variables or omitted constraints.



---

### 2. Clear & Simple Explanation

* **Fluency $\neq$ Accuracy:** Never assume a response is correct just because it reads well. A polished tone often hides factual gaps or wrong assumptions.
* **The 3-Point Check:**
    1. *Requirements:* Did Claude do everything you explicitly asked for, or did it skip the hard parts?
    2. *Source Material:* Does every claim trace back accurately to your uploaded documents?
    3. *Professional Standards:* Would this pass a human peer review in your field (e.g., correct units, logical reasoning, verified citations)?


* **The Triage Protocol:**
    * **Ready to use:** Clears all three reference checks and meets domain standards. Deploy immediately.
    * **Needs revision:** Close, but missing key facts or boundaries. Fix using a targeted, source-restricted re-prompt.
    * **Needs human override:** High-stakes risk, significant factual errors, or reliance on ungrounded training memory instead of uploaded sources. Route directly to a human expert.


* **Spotting Omissions:** Finding what is *missing* is harder than finding what is *wrong*. Always run a second, dedicated review pass specifically for completeness.

### 3. Real-World Application

#### Enterprise Insurance Claims & Policy Audit Pipeline

An automated claims-processing system extracts coverage terms from policy documents and validates patient medical claims against regulatory rules.

```
[ Incoming Patient Claim & Policy PDF ]
                   │
                   ▼
┌──────────────────────────────────────────┐
│ Stage 1: Extraction & Policy Mapping     │
│ (Claude API Parsing Claim Details)       │
└──────────────────────────────────────────┘
                   │
                   ▼
┌──────────────────────────────────────────┐
│ Stage 2: Discernment Evaluation Gate     │
│  - Check 1: Requirements (All codes parsed?) │
│  - Check 2: Source Material (Matches PDF?)   │
│  - Check 3: Professional/Regulatory Rules    │
└──────────────────────────────────────────┘
                   │
         ┌─────────┼─────────────────────────┐
         ▼         ▼                         ▼
[ Clears All ]  [ Omitted Clause ]   [ Ungrounded Regulatory Claim ]
         │         │                         │
         ▼         ▼                         ▼
┌──────────────┐┌────────────────────────┐┌────────────────────────┐
│ Ready to Use ││ Needs Revision         ││ Needs Human Override   │
│ (Auto-Pay    ││ (Source-Restricted     ││ (Escalate to Senior    │

```

* **Workflow Execution:**
* If Claude parses coverage accurately, the system marks it **Ready to Use** for automated payout.
* If Claude omits a mandatory $500 deductible condition found in the PDF, the engine flags it as **Needs Revision** and triggers a source-restricted re-prompt focusing on policy limits.
* If Claude attempts to validate state regulatory compliance without the governing law uploaded in context, the system flags it as **Needs Human Override** due to parametric memory risk in a high-stakes domain.

### 4. Key Technical Terms

* **Discernment Protocol:** A standardized evaluation procedure that measures LLM output accuracy, completeness, and fitness against requirements, source material, and professional standards.
* **Stakes Calibration:** The practice of adjusting evaluation depth and human review oversight based on the business risk and error tolerance of the domain.
* **Three-Way Triage:** A systematic classification workflow sorting generated outputs into *Ready to use*, *Needs revision*, or *Needs human override*.
* **Accuracy vs. Completeness:** A dual-axis evaluation framework where accuracy verifies the factual correctness of generated text, and completeness audits for missing critical data or context.
* **Source-Restricted Re-prompting:** An iterative prompting technique that forces the model to re-evaluate and correct its output by restricting its response boundaries strictly to uploaded source material.
* **Parametric Memory Recall:** Information generated from the model's pre-trained weights rather than explicitly provided, grounded context material.

#### Answer Key & Explanations

* **Question 1: Correct Answer: C**
*Explanation:* The output is accurate regarding rate but incomplete regarding conditional terms. Because the gap is specific and low-risk to correct automatically, the correct verdict is *Needs revision* using a source-restricted re-prompt.
* **Question 2: Correct Answer: A**
*Explanation:* Regulatory compliance is a zero-tolerance domain. Relying on parametric memory recall rather than uploaded, grounded reference documents introduces hallucination and outdated rule risks, requiring a *Needs human override* verdict.
* **Question 3: Correct Answer: B**
*Explanation:* Accuracy evaluates whether what is currently written is correct. Completeness evaluates whether any critical information or constraint was left out. Outputs can be 100% accurate while remaining dangerously incomplete.
* **Question 4: Correct Answer: C**
*Explanation:* The output met all prompt requirements, cleared internal professional standards, and operated in a low-stakes domain. Assigning *Ready to use* avoids wasting the time saved by AI automation.
