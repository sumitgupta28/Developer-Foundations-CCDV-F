### 1. Summary

The [Claude Platform & Model Foundations](https://anthropic-partners.skilljar.com/path/claude-certified-associate-foundations/claude-platform-model-foundations/486586/scorm/150nrjj19ybs6) module defines the **Capability Layer** as the set of features—specifically **Skills**, **Code Execution**, and **Memory**—that dictate what Claude can do within a selected entry point.

* **The Four-Layer Model:**
  * **Projects (Context):** Carries background knowledge and standing instructions that apply to a specific workstream.
  * **Skills (Procedures):** Defines how a specific task should be executed consistently every time. Skills live at the **account level** (not bound to a single Project) and trigger automatically across any conversation when relevant.
  * **Code Execution (Computations):** Sandboxed environment used when output requires verified computational precision rather than plausible text generation.
  * **Memory (Continuity):** Persists relevant factual state and continuity across multi-turn sessions without requiring manual context re-entry.


* **Skills Operational Characteristics:**
  * **Variance Reduction:** Skills enforce consistent procedure execution but reduce output variance without eliminating it entirely; human review remains necessary.
  * **Trust Evaluation:** Skills operate with the full session permissions granted to Claude. Third-party Skills require a strict security and trust evaluation prior to activation.

### 2. Clear & Simple Explanation

* **Entry Points vs. Capability Layer:** Entry points select *where* you work (e.g., Workbench, API, Web App), while the Capability Layer determines the *tools* available inside that environment.
* **The Four Functional Layers:**
  * *Projects:* A persistent reference binder containing your specific department rules and background documents.
  * *Skills:* A standardized checklist installed across your whole account that Claude automatically runs whenever you ask it to perform a matching task (like creating an Excel report or editing a PDF).
  * *Code Execution:* A built-in calculator/code runtime that ensures mathematical calculations and data transformations are exact rather than estimated.
  * *Memory:* A persistent notepad that carries important user facts from past chats into future sessions.


* **Key Skills Rules:** Skills help maintain process consistency, but because generative models operate probabilistically, outputs will still vary slightly. Additionally, because a Skill can read whatever data is shared in a chat, you must verify third-party Skills before turning them on.

### 3. Real-World Application

#### Architecture Scenario: Automated Financial Audit & Spreadsheet Reconciliation Engine

An enterprise accounting system automates quarterly financial ledger audits using the four-layer architecture:

1. **Project Layer (Context):** Houses SEC compliance guidelines, GAAP rules, and internal accounting standard operating procedures (SOPs).
2. **Account-Level Skill Layer (Procedures):** Activates an enterprise-wide Excel Audit Skill that automatically executes standard ledger parsing, formatting, and audit-flagging routines across any chat thread.
3. **Code Execution Sandbox (Computation):** Runs Python scripts inside a sandboxed runtime to verify formula totals, calculate variance percentages, and reconcile multi-currency balances with 100% mathematical precision.
4. **Memory Layer (Continuity):** Retains client-specific materiality thresholds and past compliance flags across sessions, preventing accountants from re-entering client parameters.
5. **Trust Evaluation Gate:** Evaluates third-party file-parsing Skills via security review before granting access to sensitive financial data.

### 4. Key Terms Note Section

**Key Technical Terms**

* **Capability Layer:** The functional suite (Skills, Code Execution, Memory) that extends base model text generation within any selected entry point.
* **Four-Layer Model:** The structural architecture defining how Projects, Skills, Code Execution, and Memory interact independently to govern context, procedures, computation, and continuity.
* **Skills:** Reusable, account-level procedures that define standardized execution steps for specific task types across all conversations.
* **Account-Level Scope:** The operational boundary of Skills, allowing them to trigger automatically across any project or chat thread under an account.
* **Code Execution:** A sandboxed execution tool that runs code to produce computationally verified results rather than text approximations.
* **Memory:** A persistence feature within the capability layer that carries relevant facts and state forward across separate sessions.
* **Variance Reduction:** The operational effect of a Skill in minimizing structural output inconsistencies across executions without making output completely deterministic.
* **Trust Evaluation:** The security governance process of inspecting a Skill’s source code and requested session permissions prior to enabling it in production environments.

* **Question 4**

* A. Enabling any third-party Skill automatically clears the active Project Knowledge Base.
* B. A Skill inherits access to all data and permissions provided to Claude during the session.

* D. Third-party Skills force all execution requests to route exclusively through Claude Haiku.

#### Answers & Explanations

* **Question 1: Correct Answer: C**
*Explanation:* According to the [Claude Platform & Model Foundations](https://anthropic-partners.skilljar.com/path/claude-certified-associate-foundations/claude-platform-model-foundations/486586/scorm/150nrjj19ybs6) material, Skills live at the account level—not inside any single Project—and Claude invokes them automatically whenever relevant in any conversation across the account.
* **Question 2: Correct Answer: A**
*Explanation:* Skills define reusable procedures and reduce process variance, but because generative models operate probabilistically, they do not eliminate output variance completely. Reviewing outputs remains an essential part of the workflow.
* **Question 3: Correct Answer: D**
*Explanation:* Code Execution is specifically designed for scenarios where results must be verified computationally correct (exact math/script evaluation) rather than merely plausible text generation.
* **Question 4: Correct Answer: B**
*Explanation:* A Skill has access to whatever data and context you provide to Claude during the active session. Therefore, a trust evaluation is required before enabling third-party Skills to prevent unauthorized data exposure.
