### 1. Summary

The [Claude Platform & Model Foundations](https://anthropic-partners.skilljar.com/path/claude-certified-associate-foundations/claude-platform-model-foundations/486586/scorm/150nrjj19ybs6) module highlights four distinct working **Core Entry Points** available within the Claude user interface: **Chat**, **Projects**, **Artifacts**, and **Research Mode**. Selecting the correct entry point before starting work dictates context persistence, standing instructions, and workflow efficiency across sessions.

* **Chat:** The default, unstructured conversational interface. It maintains short-term session history and leverages basic memory/search, but lacks structured standing instructions and curated knowledge bases. It is intended for one-off questions, exploratory prompting, and isolated tasks.
* **Projects:** Designed for recurring workstreams requiring long-term context retention, persistent standing instructions, and curated knowledge base document uploads.
* **Artifacts:** Activated when generating dedicated standalone deliverables (e.g., code files, complex documents, or diagrams) that require side-by-side viewing, iteration, or direct sharing.
* **Research Mode:[Capability]** Built for deep multi-source investigation and synthesis across extensive information, distinct from quick current-information web searches performed within standard Chat.

### 2. Clear & Simple Explanation

* **Chat:** A standard conversation box for quick, isolated questions. Once the conversation ends, the context remains in history, but you must manually paste context again if starting a fresh thread for a recurring task.
* **Projects:** A permanent workspace folder where you store background documents and set permanent instructions for Claude. Every new chat opened inside a Project automatically knows your rules and background documents.
* **Artifacts:** A dedicated pop-out window next to your chat designed for viewing and editing complete assets like code scripts, articles, or diagrams without cluttering the chat log.
* **Research Mode:** A specialized feature for conducting thorough, multi-source deep dives across large data volumes rather than answering simple single-prompt queries.

### 3. Real-World Application

#### Architecture Scenario: Enterprise Software Engineering & Architecture Review Pipeline

A software development organization establishes a standardized workflow leveraging Claude entry points for product development:

1. **Research Mode (Discovery Stage):** Architectural teams run multi-source synthesis queries to compare microservice integration frameworks against industry compliance standards.
2. **Projects (Development Workspace):** Developers configure a dedicated Project containing repository style guides, system schemas, and standing coding instructions in the Project Knowledge Base.
3. **Artifacts (Deliverable Generation):** When developers request complex OpenAPI spec files or UI component implementations inside the Project, Claude generates them in dedicated Artifact windows for side-by-side editing and code export.
4. **Chat (Ad-Hoc Support):** Individual engineers use standard Chat for quick syntax lookups or one-off regex debugging tasks that do not impact project-wide architecture.

### 4. Key Technical Terms

* **Core Entry Points:** The foundational interaction modes (Chat, Projects, Artifacts, Research Mode) within the Claude interface that define session configuration and context bounds.
* **Chat:** The default conversational entry point designed for unstructured, non-recurring tasks.
* **Projects:** A structured workspace entry point featuring standing instructions and curated knowledge bases for persistent contextual workflows.
* **Standing Instructions:** System-level prompts defined within a Project that apply persistently across all chats created under that workspace.
* **Curated Knowledge Base:** A collection of uploaded reference documents attached to a Project that provides constant context for prompts.
* **Artifacts:** Standalone dedicated UI components generated alongside chat threads for managing complex deliverables such as code, markdown documents, or SVG graphics.
* **Research Mode:** An entry point built for comprehensive multi-source investigation, deep-dive synthesis, and analytical reporting.
* **Context Persistence:** The capability to carry background knowledge, guidelines, and structural state across multiple interaction sessions without manual re-prompting.

* **Question 4**
A enterprise compliance team needs to conduct a comprehensive multi-source investigation comparing cross-border regulatory frameworks across several large policy documents. Which entry point selection logic directly matches this operational requirement?
* A. Chat thread with web search enabled
* B. Research Mode
* C. Standalone Artifact generation

---

#### Answers & Explanations

* **Question 1: Correct Answer: C**
*Explanation:* When a task outgrows Chat because background context is repeatedly pasted into new threads, transitioning to a Project allows the user to store persistent standing instructions and uploaded background files in a curated knowledge base.
* **Question 2: Correct Answer: A**
*Explanation:* Artifacts are dedicated UI windows generated when the model produces standalone deliverables (such as complete code files, documents, or diagrams) that the user needs to view, edit, or consume independently of the primary chat log.
* **Question 3: Correct Answer: D**
*Explanation:* Standard Chat is optimized for one-off questions, quick drafts, and non-recurring tasks where context does not need to persist into future sessions.
* **Question 4: Correct Answer: B**
*Explanation:* Research Mode is explicitly designated for tasks requiring deep multi-source investigation and complex information synthesis, whereas Chat web search is intended for quick current-information lookups.
