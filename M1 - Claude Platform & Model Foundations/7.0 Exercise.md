### 1. Summary

The exercise module in [Claude Platform & Model Foundations](https://anthropic-partners.skilljar.com/path/claude-certified-associate-foundations/claude-platform-model-foundations/486586/scorm/150nrjj19ybs6) focuses on holistic system configuration by evaluating four core decision levers simultaneously for any given task: **Entry Point**, **Capability Layer**, **Model Tier**, and **Context Strategy**.

* **Entry Point Selection**: Dictates the operational environment—choosing **Chat** for ad-hoc queries, **Projects** for recurring workflows requiring shared context, or **Research** for real-time web retrieval.
* **Capability Layer Integration**: Determines active execution tools—combining **Skills** (standardized templates), **Code Execution** (exact programmatic processing and math), **Memory** (user preferences), or **Artifacts** (structured deliverables).
* **Model Tier Alignment**: Matches compute needs to model characteristics—**Haiku** for high-throughput/low-cost operations, **Sonnet** as the default enterprise knowledge workhorse, and **Opus** for nuanced, high-stakes, ambiguous analysis.
* **Task Configuration Patterns**:
  * *One-off drafting*: Chat + Sonnet + Artifact.
  * *Recurring structured reporting*: Project + Skill + Sonnet.
  * *Data calculation & aggregation*: Code Execution + Haiku/Sonnet (ensuring mathematical determinism).
  * *Real-time competitor audit*: Research + Sonnet (overcoming static pre-training cutoffs).
  * *Complex multi-source policy review*: Project (Knowledge Base) + Artifact + Opus.
  * *Recurring financial variance analysis*: Project + Code Execution + Skill + Sonnet.

### 2. Clear & Simple Explanation

When designing solutions with Claude, avoid using a single default prompt setting for every problem. Instead, pick your tools using a 4-part recipe:

* **Where does the work happen? (Entry Point)**: If it's a quick one-off question, use regular Chat. If you need standard rules and shared files every time, put it in a Project. If you need current web facts, enable Web Search/Research.
* **What extra tools does the model need? (Capability Layer)**: Use **Skills** to lock in reusable templates. Use **Code Execution** whenever math or data counting is involved so the model runs Python instead of guessing numbers. Use **Artifacts** when creating standalone docs or code snippets.
* **Which brain fits the budget and complexity? (Model Tier)**: Use **Haiku** for fast, simple sorting. Use **Sonnet** for 80% of normal business writing and analysis. Use **Opus** when getting a complex contract or strategy wrong carries a high penalty.
* **Putting it together**: Match your recipe directly to the task constraints. Never pay for Opus on simple math, and never trust a standard LLM prompt alone for multi-row data calculations without Code Execution.

### Key Technical Terms

* **Entry Point**: The primary operational interface (Chat, Project, or Web Research) selected to manage conversation lifecycle, persistent state, and system context initialization.
* **Capability Layer**: Augmentative execution modules (such as Code Execution, Skills, Memory, and Artifacts) attached to a model session to enable programmatic tool execution or output isolation.
* **Code Execution**: A sandboxed runtime environment that allows an LLM to generate and execute code to perform deterministic mathematical calculations and data transformations.
* **Project Knowledge Base**: A persistent context repository within a Project workspace that automatically injects reference documents and system instructions across all session threads.
* **Skill**: A modular, reusable prompt template stored within a Project to enforce structured inputs and standardized output formats.
* **Model Tiering**: The practice of mapping specific sub-tasks to Haiku, Sonnet, or Opus based on token cost, execution speed, context limits, and reasoning capability constraints.

An HR operations team needs to process an annual survey dataset of 1,200 employee responses to calculate response rates per department and flag any group falling below a 60% completion rate. Which platform configuration correctly prevents mathematical estimation errors while optimizing cost?
* A) Chat + Artifact · Opus
* B) Research · Sonnet
* C) Code Execution · Haiku or Sonnet
* D) Project (Knowledge Base) + Skill · Opus

---
* **Question 2**
A consulting team is preparing a 20-page strategic risk analysis for a corporate board based on five uploaded market reports containing conflicting statements and ambiguous economic forecasts. Which configuration provides the necessary reasoning depth and output isolation?
* A) Project (Knowledge Base) + Artifact · Opus
* B) Chat · Haiku
* C) Research + Code Execution · Sonnet
* D) Project + Skill · Haiku

---
* **Question 3**
A finance team executes a monthly budget variance process: upload actual spending, calculate differences against stored budget baseline files, flag line items deviating by more than 10%, and output the result in a mandatory departmental report format. What is the optimal architectural setup?
* A) Chat + Artifact · Haiku
* B) Research · Opus
* C) Project (Knowledge Base) · Opus
* D) Project + Code Execution + Skill · Sonnet
---

* **Question 4**
A market analyst must compile a competitive overview detailing all product launches announced by top three industry rivals within the last 90 days. Which configuration best satisfies the contextual requirements?
* A) Project (Knowledge Base) · Opus
* B) Research · Sonnet
* C) Code Execution · Haiku
* D) Chat + Skill · Opus



---

### Answer Key & Explanations

* **Question 1**: **C) Code Execution · Haiku or Sonnet**
*Explanation*: Aggregating survey counts and computing departmental percentages requires deterministic numeric calculations. Utilizing Code Execution ensures accurate Python execution on defined datasets rather than probabilistic LLM counting, using Haiku or Sonnet for cost efficiency.
* **Question 2**: **A) Project (Knowledge Base) + Artifact · Opus**
*Explanation*: High-stakes deliverables requiring nuanced synthesis across conflicting, ambiguous multi-source inputs demand the deep reasoning ceiling of Opus, supported by a Project Knowledge Base for source documentation and Artifacts for generating the final document.
* **Question 3**: **D) Project + Code Execution + Skill · Sonnet**
*Explanation*: This recurring workflow combines multiple requirements: persistent rules and templates (Project + Skill), programmatic math verification for 10% variance thresholds (Code Execution), and balanced knowledge synthesis (Sonnet).
* **Question 4**: **B) Research · Sonnet**
*Explanation*: Querying events within the last 90 days requires real-time information retrieval that post-dates the model's static training data cutoff; enabling the Research entry point with Sonnet satisfies this requirement.
