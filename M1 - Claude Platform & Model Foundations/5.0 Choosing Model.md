### 1. Summary

[Claude Platform & Model Foundations](https://anthropic-partners.skilljar.com/path/claude-certified-associate-foundations/claude-platform-model-foundations/486586/scorm/150nrjj19ybs6) establishes the decision framework for selecting appropriate model tiers based on task complexity, execution latency, and per-call API cost token economics.

* **Haiku**: Fastest and most cost-effective tier. Built for high-volume, structured execution including entity extraction, classification, formatting, and high-throughput routine data pipelines.
* **Sonnet**: Default baseline tier for enterprise knowledge work. Balances strong reasoning with moderate speed for professional drafting, technical synthesis, standard code generation, and analytical workflows.
* **Opus**: Top-capability tier for mission-critical tasks. Optimized for deep reasoning, high ambiguity, multi-layered risk analysis, and high-stakes decision-making where output accuracy is prioritized over latency and cost.

### 2. Clear & Simple Explanation

Selecting the right model tier is an optimization problem between performance ceiling, execution speed, and budget:

* **Haiku (The High-Speed Sorting Line)**: Use when processing thousands of straightforward items per minute where execution rules are strict, speed is critical, and the risk/impact of a minor error is low.
* **Sonnet (The Knowledge Worker)**: The default recommendation for roughly 80% of enterprise AI workloads. It offers human-grade drafting and code understanding without incurring maximum latency or token costs.
* **Opus (The Senior Subject Matter Expert)**: Use for complex, high-stakes tasks. It runs slower and costs more per API call, but handles deep reasoning, ambiguous prompts, and sensitive policy evaluations.
* **Speed vs. Capability vs. Cost Trade-Off**: Higher capability tiers (Opus) consume more computational resource per call, resulting in higher latency and per-token pricing compared to lighter tiers (Haiku).

### 3. Real-World Application

**Scenario**: Enterprise FinTech Claims & Dispute Processing Pipeline

A financial platform processes 500,000 incoming customer transaction disputes daily. To minimize cost while maintaining low response latency and high resolution accuracy, the pipeline routes tasks dynamically across model tiers:

1. **Triage & Data Extraction (Haiku)**: Parses incoming unstructured emails, extracts card numbers and dispute codes into JSON schema, and flags urgent fraud alerts.
2. **Policy Verification & Drafting (Sonnet)**: Compares valid claims against transaction logs, verifies customer account terms, and generates resolution summaries for claims under $1,000.
3. **Escalation & Fraud Audit (Opus)**: Conducts multi-layered investigations on high-value claims (>$1,000), ambiguous legal disputes, and potential merchant fraud rings.

### Key Technical Terms

* **Model Tiering**: Categorizing model architectures into discrete capability levels (Haiku, Sonnet, Opus) based on execution speed, reasoning ceiling, and resource cost.
* **Latency Overhead**: The time duration required for an LLM to generate token responses back to the application pipeline.
* **Structured Data Extraction**: Transforming unformatted text into standard schema formats (e.g., JSON) for downstream programmatic execution.
* **Token Economics**: The financial cost and resource utilization calculated per input/output token processed by an API endpoint.
* **Agentic Routing**: Architecture pattern where lightweight models triage incoming inputs and direct complex edge cases to higher-capability models.

### Answer Key & Explanations

* **Question 1**: **B) Claude Haiku**
*Explanation*: Haiku is optimized for high-volume, low-latency structured extraction, parsing, and classification tasks where cost efficiency per call is the key constraint.
* **Question 2**: **C) Claude Opus**
*Explanation*: Opus is targeted at high-stakes, highly complex tasks requiring deep reasoning over multi-layered or ambiguous inputs where output quality overrides latency and token cost concerns.
* **Question 3**: **D) Haiku prioritizes fastest execution speed and lowest token cost, whereas Opus provides higher reasoning capability at greater latency and higher per-token cost.**
*Explanation*: Model capability scales directly with resource utilization: Haiku maximizes speed and throughput at low cost, while Opus maximizes reasoning ceiling at higher latency and per-token pricing.
* **Question 4**: **A) Claude Sonnet**
*Explanation*: Sonnet is designed as the baseline workhorse model for standard enterprise knowledge work, technical synthesis, drafting, and analysis.
