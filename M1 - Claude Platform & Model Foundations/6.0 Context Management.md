### 1. Summary

The module on [Claude Platform & Model Foundations](https://anthropic-partners.skilljar.com/path/claude-certified-associate-foundations/claude-platform-model-foundations/486586/scorm/150nrjj19ybs6) details strategies for context window optimization, conversation hygiene, memory curation, and usage limit management to sustain model performance during complex tasks.

* **Context Window Budget**: Every session operates under a finite working-memory limit. As messages accumulate, earlier context compresses via automated summarization, which can lead to instruction drift or missing early-session constraints.
* **Degradation Signals**: Key indicators that context requires intervention include Claude ignoring initial instructions, focusing exclusively on recent exchanges, or exhibiting noticeable drops in reasoning accuracy.
* **Intervention Framework**:
  * **Restart**: Initiate a clean session when a thread strays or shifts focus. Standing instructions and Project Knowledge Base assets persist automatically across restarts.
  * **Summarize**: Generate a state recap (decisions made, work in progress, open issues) and transfer it as initial context into a fresh session.
  * **Persist**: Store static, recurring requirements into Memory or Project Knowledge Bases rather than repeatedly supplying them in prompts.


* **Memory Curation**: Stored facts require continuous auditing and pruning; outdated memory entries actively degrade response precision over time.
* **Usage Quota Management**: Complex projects should be partitioned into modular segments with interim states saved to knowledge bases to avoid hitting rolling session windows or weekly tier quotas.

### 2. Clear & Simple Explanation

* **Context Window as Working RAM**: Think of the context window as short-term memory. When filled with too much conversation, older details get summarized and fine nuances can be lost.
* **Spotting Context Fatigue**: If Claude forgets rules established at the start of a session or only answers based on your last prompt, your working memory is exhausted.
* **The Three-Step Recovery Plan**:
  * **Restart**: Start fresh whenever a conversation gets cluttered or a new sub-task begins.
  * **Summarize & Handoff**: Ask Claude for a status briefing of key findings, copy that recap, and open a new chat with it.
  * **Persist to Knowledge Base**: Put permanent rules (like API guidelines or project style guides) into the Project Knowledge Base so they survive thread resets.
  

* **Memory Pruning**: Regularly clean out stored memories—outdated rules in long-term memory are worse than no memory at all.
* **Pacing Long Workflows**: Break giant projects into smaller steps so you don't run out of usage limits mid-task.

### 4. Key Technical Terms

* **Context Window**: The maximum volume of token input and output history an LLM can hold in active working memory during a single session.
* **Instruction Drift**: A degradation pattern where a model gradually stops adhering to initial prompt instructions as the session length increases.
* **State Summarization**: Extracting essential decisions, open items, and progress from an active thread to bootstrap a clean session without carrying over bloated history.
* **Memory Curation**: The process of auditing, updating, and deleting expired facts in long-term model memory to prevent hallucination or stale context.
* **Project Knowledge Base**: A persistent context repository associated with a Project that automatically provides standing instructions and background documentation across all new sessions.
* **Rolling Session Window**: A temporary rate-limiting window enforced by model API/platform infrastructure to regulate continuous high-volume usage.

### Answer Key & Explanations

* **Question 1**: **B) Request a summary of decisions made and current progress, start a new conversation, and paste the summary as the opening context.**
*Explanation*: When context degrades and instruction drift occurs due to context window compression, generating a state summary and restarting in a fresh thread restores full reasoning clarity while maintaining task continuity.
* **Question 2**: **C) Uncurated, outdated entries in Memory or the Project Knowledge Base are polluting the prompt context.**
*Explanation*: Stale memory entries and uncurated knowledge base files persist across sessions and can actively degrade precision by providing outdated context to the model.
* **Question 3**: **B) Project standing instructions and uploaded Knowledge Base files**
*Explanation*: Restarting a conversation clears the specific thread message history but automatically retains standing project instructions and knowledge base documentation across sessions.
* **Question 4**: **C) Segmenting work into modular sub-tasks, saving interim outputs to the knowledge base, and restarting sessions from state summaries.**
*Explanation*: Partitioning large tasks and preserving progress in the knowledge base prevents session loss when working under rolling session limits and high-tier usage budgets.
