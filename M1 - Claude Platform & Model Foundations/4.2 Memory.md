### 1. Summary

The [Claude Platform & Model Foundations](https://anthropic-partners.skilljar.com/path/claude-certified-associate-foundations/claude-platform-model-foundations/486586/scorm/150nrjj19ybs6) course details **Memory** as a core component of the Capability Layer that retains work-relevant facts across multi-turn interactions and separate sessions, eliminating redundant prompt setup:

* **Cross-Session Fact Retention:** Memory stores persistent contextual data—such as recurring user roles, output formatting preferences, collaborator names, and standing project constraints—to streamline ongoing workflows.
* **Memory Curation Lifecycle:** To prevent factual drift, active curation is required. Outdated facts degrade output quality; active users must review, update, or purge stale entries at least monthly.
* **Project-Scoped Isolation:** Memory boundaries strictly mirror Project containers. Context from one Project (e.g., Client A) is completely isolated and cannot leak into another (e.g., Client B).
* **Incognito Mode Governance:** Standalone chats created in Incognito Mode suppress both chat history logging and Memory generation. This provides a temporary container for confidential inputs without overriding underlying organizational data retention policies.
* **Memory Import & Fallback Mechanics:** As of June 2026, Memory import is an experimental feature supported on Free, Pro, Max, and Team plans (excluding Enterprise). When automated import pathways are unavailable, the documented architectural fallback is manual ingestion via Memory Settings—*not* populating a Project's Knowledge Base.

### 2. Clear & Simple Explanation

* **Memory:** Claude's persistent notebook that remembers key details across chats, so you don't have to repeat your preferences, role, or constraints every time.
* **Memory Curation:** Regularly clearing out old or outdated memories so Claude doesn't rely on obsolete instructions.
* **Project-Scoped Memory:** A strict partition that keeps memories inside their assigned Project folder, ensuring private notes for one client never leak into chats for another.
* **Incognito Mode:** An "off-the-record" mode for standalone chats that stops Claude from saving new memories or chat logs, ideal for sensitive or exploratory tasks.
* **Memory Import Fallback:** The official backup method when migrating memories from other platforms: if auto-import fails, type key facts directly into Memory Settings rather than dumping them into document folders.

### 3. Real-World Application

#### Architecture Scenario: Multi-Tenant Enterprise Consultancy Platform

A consulting firm manages separate client engagements (Client Alpha and Client Beta) with strict data separation requirements while onboarding legacy rules from another AI platform:

1. **Project Isolation Boundary:** Separate Projects are provisioned for Client Alpha and Client Beta. Project-Scoped Memory ensures proprietary compliance rules for Client Alpha never bleed into Client Beta sessions.
2. **Confidential Ingestion Gateway:** Senior partners conduct M&A risk evaluations in **Incognito Mode** outside Projects to prevent sensitive deal terms from persisting in chat history or auto-populating Memory.
3. **Legacy Fact Migration:** Onboarding team preferences from a legacy system is executed via the **Manual Memory Settings Fallback** rather than cluttering the Project Knowledge Base.
4. **Curation Lifecycle Governance:** Operations managers perform monthly Memory Curation reviews, purging expired client mandates to maintain output accuracy.

### 4. Key Technical Terms

**Key Technical Terms**

* **Memory:** A Capability Layer feature that persists work-relevant facts, role context, and constraints across multi-turn chats.
* **Memory Curation:** The active process of auditing, updating, and deleting stored cross-session facts to avoid stale context drift.
* **Project-Scoped Memory:** Context isolation mechanism that binds stored memories strictly to their parent Project container to prevent cross-domain data leakage.
* **Incognito Mode:** A session state for standalone chats that prevents history logging and memory formation while adhering to organizational data retention rules.
* **Memory Import:** An experimental feature (as of June 2026) allowing migration of stored facts from external AI platforms across select plan tiers.
* **Manual Memory Settings Fallback:** The technical protocol of entering facts directly into Memory Settings when automated platform import is unavailable.
* **Data Retention Policy:** Organization-level compliance rules that govern logging and data storage independently of user-facing UI toggles like Incognito Mode.

### 5. Exam Practice

* **Question 1**
A technical lead oversees two separate client projects, Project Red and Project Blue. The lead notices that formatting constraints defined in Project Red sessions are appearing in Project Blue outputs. According to the [Claude Platform & Model Foundations](https://anthropic-partners.skilljar.com/path/claude-certified-associate-foundations/claude-platform-model-foundations/486586/scorm/150nrjj19ybs6) memory model, what is the root cause?
* A. Memory automatically synchronizes across all account Projects by default.
* B. The lead reached the token budget limit on Project Blue, causing context cross-contamination.
* C. The constraints were saved in global Memory outside a Project container, whereas setting up separate Projects isolates Project-Scoped Memory.
* D. The user enabled Incognito Mode, which forces all Project memories to merge globally.


* **Question 2**
A Team plan admin attempts to migrate legacy system prompts and user preferences from an external AI tool. The automated memory import path fails during execution. According to official platform guidelines, what is the correct fallback strategy?
* A. Add the key facts manually through the memory settings interface.
* B. Upload the legacy preference files directly into the Project Knowledge Base.
* C. Contact Enterprise Support to request an automated platform override.
* D. Execute an API call to force context re-hydration across active chat threads.


* **Question 3**
A developer needs to execute an exploratory code analysis using highly confidential credentials that must not leave a trace in session history or persist in model memory. However, enterprise compliance mandates strict underlying data retention. Which approach meets these requirements?
* A. Create a permanent Project Knowledge Base file and delete it after execution.
* B. Run the session using a custom Skill with Memory Curation disabled.
* C. Append a system prompt instructing Claude to erase its context budget upon completion.
* D. Conduct the session in Incognito Mode outside Projects.


* **Question 4**
A technical writer notices that Claude's generated output frequently includes an outdated corporate style guide rule that was replaced six months ago. Which governance operational procedure was neglected?
* A. Enabling system prompt cache pinning on every query.
* B. Performing periodic Memory Curation to update or purge stale entries.
* C. Switching the primary execution tier from Claude Sonnet to Claude Opus.
* D. Re-importing memories from an external platform via the experimental pathway.



---

#### Answers & Explanations

* **Question 1: Correct Answer: C**
*Explanation:* Memory is scoped to Projects. Context saved inside a specific Project does not spill into another Project. If context leaks across workstreams, it was likely saved at the account/global level outside separate Project boundaries.
* **Question 2: Correct Answer: A**
*Explanation:* The documented fallback when the automatic memory import path is unavailable is to manually add key facts through memory settings, rather than routing them into a Project's Knowledge Base.
* **Question 3: Correct Answer: D**
*Explanation:* Incognito mode keeps standalone chats out of Memory and chat history while still respecting organizational underlying data retention requirements.
* **Question 4: Correct Answer: B**
*Explanation:* Stale memories lead to misleading outputs over time. Platform guidelines recommend performing active Memory Curation at least monthly to purge or update obsolete facts.
