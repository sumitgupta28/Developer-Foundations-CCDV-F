### 1. Summary

* **Problem Statement:** When creating multiple downstream deliverables (such as staff announcements, FAQs, and executive briefings) from a single dense source document, attempting to generate all outputs directly from raw context risks propagating misreadings, hallucinated facts, or key omissions across all documents simultaneously.
* **Core Concepts:**
  * **Shared Extraction Foundation:** Decoupling the extraction of core facts from the formatting of target deliverables to establish a single, unified baseline.
  * **Verification Checkpoint:** Introducing a explicit validation step between raw data extraction and downstream artifact generation to halt error propagation.
  * **Sequential-to-Parallel Task Decomposition:** Structuring prompt workflows so that high-stakes extraction runs and validates first, followed by downstream generation tasks that reference only the verified baseline.


* **Key Technical Takeaways:** As outlined in the [Prompting & Task Execution](https://anthropic-partners.skilljar.com/path/claude-certified-associate-foundations/prompting-task-execution/486636/scorm/2dk4fzu1k4lj) training module, multi-deliverable prompt workflows must sequence shared, high-stakes factual extraction first to build a verified foundation before launching parallel draft generations.

---

### 2. Clear & Simple Explanation

* **The Single-Pass Flaw:** If you ask an LLM to take a 20-page policy update and immediately write three different documents (an email for employees, an FAQ, and a summary for executives), the model has to interpret, filter, and format everything at once. If it misinterprets a rule in step one, that exact mistake gets copied into all three final documents.
* **The "Extract First, Build Second" Pattern:**
  * **Step 1 (Extract):** Pull out only the substantive facts and practical implications from the raw document.
  * **Step 2 (Verify):** Confirm that this list of extracted facts is 100% accurate and complete before drafting anything else.
  * **Steps 3–5 (Target Drafts):** Use only the verified extraction list as input to draft the staff email, the FAQ, and the executive briefing.


* **Why This Works:** Separating fact-finding from audience-specific writing ensures high reliability, prevents duplicated errors, and makes intermediate auditing simple.

### 3. Real-World Application

#### Enterprise Infrastructure Migration Communication Engine

In an enterprise cloud migration, an architectural team must process a 50-page infrastructure assessment and produce three collateral pieces: an operational runbook for Site Reliability Engineers (SREs), a developer schedule notification, and an executive risk summary for C-suite leadership.

Rather than passing the 50-page document into isolated prompts or a single massive prompt, the system executes a decomposed workflow:

```
[ 50-Page Architectural Migration PDF ]
                   │
                   ▼
┌──────────────────────────────────────────┐
│ Step 1: High-Stakes Technical Extraction │
│ (Downtime windows, API changes, risks)   │
└──────────────────────────────────────────┘
                   │
                   ▼
┌──────────────────────────────────────────┐
│ Step 2: Automated & Human Audit Gate    │
│ (Verify extracted dates & API specs)     │
└──────────────────────────────────────────┘
                   │
         ┌─────────┴─────────┐
         ▼                   ▼
┌──────────────────┐┌──────────────────┐
│ Step 3: Draft    ││ Step 4: Draft    │
│ SRE Runbook      ││ Dev Schedule     │
└──────────────────┘└──────────────────┘
         │
         ▼
┌──────────────────────────────────────┐
│ Step 5: Draft Exec Summary           │
└──────────────────────────────────────┘

```

* **Workflow Architecture:**
1. **Extraction Stage:** Claude parses the raw technical assessment to extract a structured Markdown list containing breaking changes, scheduled outage windows, and API deprecations.
2. **Audit Gate:** An automated schema check or human lead validates the extracted outage windows against system records.
3. **Targeted Generation:** The confirmed extraction serves as the single source of truth for generating the SRE Runbook, Developer Notice, and Executive Briefing concurrently or sequentially.

### Key Technical Terms

* **Task Decomposition:** The prompt engineering technique of breaking down a complex, multi-part task into a structured sequence of smaller, discrete prompt execution steps.
* **Shared Extraction Foundation:** The initial stage of a decomposed workflow where core data, facts, or changes are extracted into a single verified baseline used by all subsequent generation steps.
* **Error Propagation:** The cascading effect where an unverified mistake or misinterpretation made in an initial processing step is copied into all downstream outputs derived from that step.
* **Verification Checkpoint:** An explicit validation stage (automated or human-in-the-loop) introduced between extraction and generation to confirm accuracy before proceeding.
* **Parallel Deliverables:** Multiple distinct target documents or artifacts (e.g., FAQs, executive briefings, announcements) generated from the same core underlying facts or source material.
