### 1. Summary

The [Prompting & Task Execution: Task Decomposition](https://anthropic-partners.skilljar.com/path/claude-certified-associate-foundations/prompting-task-execution/486636/scorm/2dk4fzu1k4lj) module establishes architectural patterns for breaking complex, multi-stage requests into structured, sequential execution chains.

* **Single-Prompt Degradation**: Packing multi-stage tasks (e.g., deriving criteria, scoring items, analyzing trade-offs, and recommending solutions) into a single prompt forces simultaneous reasoning passes, resulting in superficial execution across all stages and unexplainable outputs.
* **Task Decomposition**: Dividing complex requests into discrete, ordered steps executed sequentially. Each step generates a checkable intermediate result, enabling early error detection (e.g., catching incorrect criteria in Step 1 prior to scoring in Step 2) and ensuring auditable reasoning.
* **Conversation Lifecycle Management**:
  * *Single Conversation Thread*: Retain sequential steps within one session when subsequent steps depend directly on preceding outputs stored in active short-term context.
  * *Thread Isolation*: Transition to a fresh conversation thread when tasks are fully independent or when accumulated message history triggers early context degradation.

### 2. Clear & Simple Explanation

* **The Monolithic Prompt Problem**: Asking Claude to "evaluate three vendors and pick one" in a single prompt forces the model to invent rules, calculate scores, weigh trade-offs, and make a decision all at once. The result is often vague, rushed, and hard to verify.
* **The Assembly Line Solution (Decomposition)**: Treat complex prompts like a physical assembly line. Step 1 defines the evaluation criteria. Step 2 scores each candidate against those criteria. Step 3 highlights key trade-offs. Step 4 generates the final recommendation based strictly on the prior outputs.
* **Early Error Detection**: If your evaluation criteria in Step 1 are flawed, you can correct them immediately before scoring begins. In a single giant prompt, you wouldn't notice a criteria error until after the final recommendation was generated.
* **Context vs. Fresh Start**: Keep related steps in the same chat so the model remembers earlier findings. If a step doesn't depend on past history—or if the chat has become long enough that early instructions get blurry—start a new chat session.

### Answer Key & Explanations

* **Question 1**: **B) Running multiple complex reasoning steps in a single prompt causes shallow execution across all steps.**
*Explanation*: Packing derivation, scoring, ranking, and code writing into a single prompt forces simultaneous reasoning passes, resulting in superficial work across all sub-tasks.
* **Question 2**: **A) Maintain all steps within a single conversation thread so later steps retain access to prior outputs in context.**
*Explanation*: Sequential steps that depend directly on prior intermediate outputs should remain in the same conversation thread so subsequent prompts can reference preceding state.
* **Question 3**: **C) It produces checkable intermediate results that allow errors to be caught before downstream steps execute.**
*Explanation*: Decomposition breaks complex logic into auditable sub-tasks. Catching a mistake in Step 1 (e.g., incorrect criteria) prevents flawed downstream scoring and recommendations.
* **Question 4**: **B) Generate a state summary of current progress and initiate a fresh conversation thread to clear context fatigue.**
*Explanation*: When long conversation history causes instruction drift or context fatigue, extracting a state recap and restarting in a clean thread restores full reasoning precision.

### Key Technical Terms

* **Task Decomposition**: Splitting a multi-part, complex request into discrete, ordered steps executed sequentially to maintain reasoning depth and precision.
* **Single-Prompt Failure Pattern**: Performance degradation occurring when multiple distinct reasoning stages are packed into a single instruction pass.
* **Checkable Intermediate Result**: An auditable output produced at a specific stage of a decomposed chain that can be verified before proceeding to downstream steps.
* **Auditable Reasoning**: An execution trace where final model decisions can be explicitly traced back through intermediate step outputs.
* **Early Context Degradation**: The drop in model adherence and output accuracy caused by an excessively long conversation context history.
* **Thread Isolation**: The practice of splitting independent sub-tasks into separate conversation sessions to prevent context clutter.
