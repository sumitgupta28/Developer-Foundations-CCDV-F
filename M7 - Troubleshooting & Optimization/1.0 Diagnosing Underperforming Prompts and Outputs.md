### 1. Problem statement

Developers routinely respond to AI prompt underperformance by either giving up—concluding that Claude cannot perform the task—or engaging in "thrashing" by changing random parameters without identifying the root cause. Without a structured diagnostic sequence, teams waste engineering cycles repeating manual corrections rather than implementing persistent architectural fixes for issues such as under-specification, context overload, feature/model mismatches, or stale configurations.

---

### 2. Summary

The [Troubleshooting & Optimization](https://anthropic-partners.skilljar.com/path/claude-certified-associate-foundations/troubleshooting-optimization/486642/scorm/3116chkqltc8i) module details a systematic diagnostic and optimization framework for identifying root causes and building persistent workflow enhancements:

* **Diagnostic Sequence vs. Random Thrashing**: Replaces trial-and-error prompt modifications with a structured sequence to isolate and resolve underperformance failure modes.
* **Four Root Causes of Prompt & Output Underperformance**:
  * **Under-Specification**: Instructions that lack explicit constraints, required schemas, edge-case guidance, or clear formatting requirements.
  * **Context Overload**: Excess or noise-heavy prompt payloads that saturate the context window, causing instruction attenuation or missed detail retrieval.
  * **Wrong Feature or Model**: Misaligning task complexity with model capabilities (e.g., using lightweight models for complex reasoning) or selecting inadequate architectural features (e.g., standard prompts instead of function calling/Skills).
  * **Stale Configuration**: Outdated system instructions, deprecated tool definitions, or legacy project settings overriding active operational rules.


* **Persistent Feedback Integration**: Converting manual, recurring human corrections into permanent system updates across standing instructions, tool definitions, and system prompts.
* **Workflow Optimization & Infrastructure Promotion**: Enhancing operational efficiency by promoting shared context, standardized formats, and automated verification steps into structured assets (Projects, Skills, and standing instructions).

---

### 3. Clear & Simple Explanation

* **Stop Guessing, Start Diagnosing**: When an output fails, do not change random prompt words. Follow a step-by-step diagnostic check to see if the instructions were vague, the prompt had too much clutter, the wrong model/feature was picked, or an old configuration interfered.
* **Fix Root Causes Permanently**: If you find yourself manually correcting Claude for the same formatting or logic mistake repeatedly, edit the underlying prompt, Skill, or project configuration so the fix is permanent.
* **Promote Workflows into Reusable System Assets**: Move repeated boilerplate context, output templates, and validation steps out of casual chat prompts and into reusable system assets like custom Skills, Projects, and standing instructions.

### 5. Key Terms Note Section

Troubleshooting AI applications under the [Troubleshooting & Optimization](https://anthropic-partners.skilljar.com/path/claude-certified-associate-foundations/troubleshooting-optimization/486642/scorm/3116chkqltc8i) framework requires executing a **Diagnostic Sequence** rather than engaging in **Random Thrashing**. Developers isolate issues among four failure patterns: **Under-Specification**, **Context Overload**, **Wrong Feature or Model**, and **Stale Configuration**. Recurring human feedback must be converted into **Persistent Fixes** by promoting shared context, schemas, and **Verification Steps** into **Standing Instructions**, **Projects**, and **Skills**.

**Key Technical Terms**

* **Diagnostic Sequence**: A systematic, step-by-step troubleshooting methodology used to identify the root cause of AI underperformance.
* **Random Thrashing**: The inefficient practice of making arbitrary, trial-and-error changes to prompts without diagnosing the underlying cause of failure.
* **Under-Specification**: A prompt flaw where instructions lack explicit constraints, required formats, or boundary conditions.
* **Context Overload**: The degradation of output quality caused by injecting excessive or irrelevant data into the context window.
* **Wrong Feature or Model**: An architectural mismatch where the selected model tier or system capability is ill-suited for the task's complexity.
* **Stale Configuration**: An operational error where outdated system instructions, legacy project settings, or deprecated tool schemas override current requirements.
* **Persistent Fixes**: Updating permanent prompt templates, Skills, or system configurations to prevent recurring manual corrections.
* **Standing Instructions**: System-level rules and constraints that persist across multiple execution sessions.
* **Skills**: Reusable executable tools or defined capabilities that extend model functionality for specific workflows.
* **Projects**: Organized workspaces that combine standing instructions, shared document context, and team collaboration settings.
* **Verification Steps**: Programmatic or structured check gates embedded into workflows to validate model output compliance before final execution.
